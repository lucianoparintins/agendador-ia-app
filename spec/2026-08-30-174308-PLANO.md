# Plano: Agendador IA — REST + Ollama Local + SQLite

## Objetivo
Serviço REST em FastAPI que recebe mensagens de chat para agendamento de serviços (barbearia/salão), consulta o modelo Ollama local `gemma2:2b`, e retorna resposta conversacional + agendamento estruturado em JSON, com persistência em SQLite.

- Ollama local em `http://localhost:11434` (ativo), modelo padrão `gemma2:2b`
- Framework: FastAPI + uvicorn + httpx (async)
- Persistência: SQLite nativo (`sqlite3`), banco em `app/agendamento.db`

## Modelo de dados (SQLite)
1. **sessoes**: `id PK AUTOINCREMENT`, `titulo TEXT`, `criado_em TEXT`
2. **mensagens**: `id PK`, `sessao_id FK`, `role TEXT` (user/assistant), `conteudo TEXT`, `criado_em TEXT`
3. **agendamentos**: `id PK`, `sessao_id FK`, `cliente TEXT`, `servico TEXT`, `data TEXT`, `hora TEXT`, `status TEXT` (rascunho/confirmado), `criado_em TEXT`

O histórico da conversa é reconstruído no servidor a partir de `sessao_id`.

## Endpoints
- `POST /chat` — `{ sessao_id?, mensagem }` → carrega histórico, persiste msg user, envia ao Ollama, persiste resposta, extrai agendamento. Retorna `{ sessao_id, reply, agendamento? }`
- `GET /sessoes` — lista sessões
- `GET /sessoes/{id}/mensagens` — histórico de uma sessão
- `GET /agendamentos` — lista agendamentos persistidos
- `GET /health` — verifica Ollama (`/api/tags`)

## ollama_client.py
- `httpx.AsyncClient` → `POST /api/chat`, modelo `gemma2:2b`, `stream=False` (resposta completa; streaming fica para 2ª versão)
- `messages` = system prompt (pt-BR: papel de assistente de agendamento + instrução para retornar JSON `{cliente, servico, data, hora}`) + histórico + nova mensagem
- Parser extrai bloco JSON via regex; fallback retorna campos capturados até agora mesmo sem JSON perfeito
